# Catalogo della strumentazione con MCP — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (esecuzione nativa, scelta dell'utente). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** un server MCP `catalogo_mcp` con tre strumenti sugli apparecchi del laboratorio e un client MCP generalizzato a più server.

**Architecture:** `catalogo_mcp/` come `calcolatrice_mcp/`: logica pura (`apparecchi.py`) + FastMCP su stdio (`server.py`) + dati in `apparecchi.json`. `assistente/client_mcp.py` passa da un server fisso a un elenco di `ServerMCP`, con una discovery per server; il resto dell'agente vede strumenti sincroni ordinari.

**Tech Stack:** Python 3.14.7, `mcp==1.30.0` (FastMCP), `langchain-mcp-adapters==0.3.2`, pytest. Nessuna dipendenza nuova.

**Spec:** `docs/superpowers/specs/2026-11-09-catalogo-design.md`

## Global Constraints
- Stati ammessi: `disponibile`, `in uso`, `in manutenzione`, `fuori servizio`. Date nel JSON `AAAA-MM-GG`, mostrate `GG/MM/AAAA`.
- Messaggi in italiano; gli errori del server arrivano al modello senza il prefisso `Error executing tool …` (già tolto dal client).
- `catalogo_mcp/` non importa nulla da `assistente/`; `asyncio` e `langchain_mcp_adapters` solo in `assistente/client_mcp.py`.
- Branch `feature/catalogo`; Conventional Commits in italiano con `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; staging selettivo; niente merge né push.

## Review Focus
1. Maiuscole e spazi: `cerca_apparecchi("CENTRIFUGA")`, `elenca_apparecchi(stanza=" b12 ", stato="In Manutenzione")` funzionano. Test in Task 1.
2. Codice inesistente o in minuscolo (`mic-02` trovato; `XYZ-99` errore). Test in Task 1.
3. Uno dei due server che non parte: errore d'avvio che nomina quel server. Test in Task 2.
4. Errore di trasporto con il nome del server giusto (`catalogo`, non `calcolatrice`). Test in Task 2.
5. JSON malformato o con stato non ammesso: il server non parte, messaggio chiaro su stderr. Test in Task 1.
